# OmniWM

[OmniWM](https://omniwm.app) is the tiling window manager. It also draws the workspace bar, which replaces the macOS menu bar, and the focus border. Its own hotkeys are off: Karabiner drives it through `omniwmctl` and the helper scripts ([karabiner.md](karabiner.md)).

## Files

| Path | Tracked | Managed by | Purpose |
|---|---|---|---|
| `.config/omniwm/settings.toml` | yes | hybrid | OmniWM's whole configuration. OmniWM rewrites it from its Settings window; the Karabiner build generates `[[workspaces]]` and the `assignToWorkspace` `[[appRules]]` and keeps every other rule |
| `.config/omniwm/shell/shell.toml` | yes | hybrid | Bar overrides (`[profiles.default]`): widget layout and `workspaceBar` style. OmniWM's Settings window writes it; hand edits apply too |
| `.config/omniwm/shell/` (everything else) | no | app | OmniWM-managed profiles, widgets and type definitions, updated with each release |
| `.config/omniwm/scripts/*.sh` | yes | manual | One script per action that needs state or several calls |
| `.config/omniwm/scripts/lib.sh` | yes | manual | Shared helpers and the `OMNIWM_*` settings with their defaults |
| `.config/omniwm/scripts/displays.sh`, `displays.jq` | yes | manual | Display routing and pointer helpers, sourced after `lib.sh` |
| `.config/omniwm/scripts/show-menu-bar.sh` | yes | manual | Turns macOS menu bar auto-hide back off, see below |
| `Library/LaunchAgents/dots.show-menu-bar.plist` | yes | manual | Runs `show-menu-bar.sh` at login and whenever the global preferences change |
| `~/Library/Logs/dots.show-menu-bar.log` | no | scripts | Errors of `show-menu-bar.sh` |
| `.config/karabiner-config/src/apps.json`, `workspaces.ts` | yes | manual | Workspace keys, and each app's workspace and key, see below |
| `~/.local/state/omniwm/`, `~/.local/state/omniwm-helper/` | no | app / scripts | OmniWM's runtime state and the scripts' pull state |

## How it works

### settings.toml

- OmniWM reloads the file on save and rewrites it in canonical form (sorted keys, no comments) whenever a setting changes, so it often shows up as modified. Validation is strict: a missing key, an unknown enum value or a duplicate hotkey id rejects the whole file.
- Values the Karabiner setup relies on: `general.hotkeysEnabled = false` and every binding `"Unassigned"`, `general.ipcEnabled = true` (`omniwmctl` needs it), `niri.moveWindowStacksIntoColumn = false` (the move keys swap columns, the join keys consume or expel), `workspaceBar.hideEmptyWorkspaces = true` (39 workspaces exist), `quakeTerminal.enabled = true` with `provider = "ghostty"` (left ⌘⌥⏎), the app rules not generated by the build (minimum window sizes, floating 1Password, which Hyper + p toggles, and dictation apps), and ⌃⌘-drag to move or resize tiled windows. Everything else (gaps, border, animations, gestures, default layout) is plain preference.
- The bar uses OmniWM's default shell style, which `shell/shell.toml` moves to the bottom edge (`position = "bottom"`, full width). The style's own `[workspaceBar]` in `shell/default/shell.toml` overrides the matching `settings.toml` keys, so bar position, height, width, background and labels belong in `shell/shell.toml`.
- The macOS menu bar always shows. OmniWM 0.8.0 turns on macOS menu bar auto-hide for every full-width bar not set to `belowMenuBar`, even at the bottom ([OmniWM#1270](https://github.com/OmniNull/OmniWM/issues/1270)), and restores it on quit; its `apple-menu` and `app-menu` widgets render only while it does. The `dots.show-menu-bar` LaunchAgent watches `~/Library/Preferences/.GlobalPreferences.plist` and runs `show-menu-bar.sh`, which turns auto-hide off again within a second or two. OmniWM sets auto-hide only when its own request changes (at launch, on a settings reload that turns it on, after a Hidden Bar menu closes), so the two don't fight. Auto-hide set in System Settings is undone too. A bar that isn't full width needs neither.
- `routing` holds the monitor grid from OmniWM's Monitor Setup, keyed by this machine's display UUIDs; `mode = "macOS"` follows the macOS arrangement instead.

### Workspaces and apps

- Workspace keys are `1–9`, `0`, `a–z`, `ä ö ü`, in that order (`workspaceKeys` in `workspaces.ts`). OmniWM only accepts positive integers as names, so the key at position *i* becomes workspace `i + 1` with the upper-case key as `displayName` (`1` → `1`, `0` → `10`, `a` → `11`/`A`, `ü` → `39`). Native `omniwmctl` calls use the number, resolved at build time; the scripts take keys and look workspaces up by display name.
- New workspaces get the home monitor `main`, except `4–6` (`secondary`) and `7–9` (`tertiary`). A home changed later in OmniWM's Settings window survives the build.
- `apps.json` lists the apps, each as `{ "workspace": "t", "key": "t", "bundleId": "…" }`. `workspace` is the app's default workspace, which several apps can share. `key` is optional and belongs to one app only; it doesn't have to match the workspace (Claude has `l` and lives on `i`). An app without a key (Rex) gets its workspace but no Hyper binding. The workspace feeds the generated `assignToWorkspace` rules (OmniWM applies them only while the app has no windows, so its first window lands there) and `move-to-default.sh` / `move-all-to-default.sh` (unlisted apps go to `q`). The key feeds Karabiner: Hyper + key cycles the app's windows or launches it, ⌃ + Hyper + key pulls one of its windows to the workspace under the pointer.

### Scripts

- Bindings use a native `omniwmctl` command whenever one does the job. The scripts (`cycle.sh`, `pull.sh`, `summon.sh`, `close-others.sh`, …) are named after their action and need bash 5 and `jq` (`/usr/bin/jq` ships with macOS). They take settings from `OMNIWM_*` environment variables (defaults at the top of `lib.sh`), print errors on stderr and exit 1. `cycle.sh` also exits 1 when the app has no windows, so Karabiner launches it.
- `omniwmctl command move-to-workspace` doesn't make focus follow the window, so `move-window.sh` moves it by id and then navigates to it.
- OmniWM moves a workspace only to an *adjacent* monitor (`omniwmctl workspace move-to-monitor --force`, a runtime override that a settings reload clears). `displays.sh` reads the routing grid from `settings.toml` with `awk` (relying on OmniWM's canonical layout), finds a route with the jq functions in `displays.jq`, hops along it and restores what the displays in between showed. It reads and moves the pointer through `osascript -l JavaScript`.

## Changing it

- Change preferences in OmniWM's Settings window. When a value must be set by hand, change it in place and never delete keys.
- Workspaces and app rules: edit `apps.json` or `workspaces.ts`, run the Karabiner build, and stage `apps.json`, `karabiner.json` and `settings.toml` together. Find a bundle ID with `mdls -name kMDItemCFBundleIdentifier -r /Applications/<App>.app`.
- Only append to `workspaceKeys`. Inserting a key renumbers every later workspace, and OmniWM keeps windows on their workspace *number* across a reload.
- Every write of `settings.toml` makes OmniWM reload, which drops runtime workspace-to-monitor moves; the build skips unchanged writes for this reason.
- Track only files you add under `shell/`. The `a` simlayer opens the folder (`c`) and restarts OmniWM (`r`).
- After editing the LaunchAgent, reload it: `launchctl bootout gui/$(id -u)/dots.show-menu-bar; launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/dots.show-menu-bar.plist`. Once #1270 is fixed, boot it out and delete it with `show-menu-bar.sh`.

## Per-machine setup

- Grant OmniWM Accessibility and Input Monitoring.
- Turn on Start at Login in OmniWM's Settings (macOS stores it, not `settings.toml`).
- Keep "Displays have separate Spaces" on, and run Monitor Setup when the displays change.
